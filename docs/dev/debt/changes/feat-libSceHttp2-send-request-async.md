# libSceHttp2

## change [libSceHttp2 asynchronous requests]

- [libSceHttp2 asynchronous requests](../../../core/libs/prx/libSceHttp2/Export.cpp) - `sceHttp2ReadDataAsync` returns `0x80436063` unconditionally, matching the bundled module's `mov eax; ret` body, so no read result is produced. `sceHttp2SendRequestAsync` takes the request transport the same way `sceHttp2SendRequest` does, runs the synchronous `Send` on the calling thread, then triggers the caller's user event and queues one 24-byte `Http2AsyncResult` whose `result` is the send's return code: `0` on success, the measured send error otherwise, and `0x80431063` under `APS5_NET_DISCONNECTED`, where `Send` fails before connecting. A non-null `option` argument and a failing `sceKernelTriggerUserEvent` still throw. Because the send is synchronous, the completion is queued before the call returns and no request work runs on a library thread; the console's completion timing, thread, event types, async-buffer ownership, timeout handling and cancellation results are unverified. `sceHttp2WaitAsync` validates a non-null `result`, a null `option` and a live request, then drains a queued result with or without `APS5_NET_DISCONNECTED`; the module aborts on an empty queue and never reads `timeout`, so an empty drain still throws.
